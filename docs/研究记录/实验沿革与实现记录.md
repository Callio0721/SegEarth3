## 1. 方法如何收敛

| 阶段 | 实际探索 | 留下的认识 | 当前处理 |
|---|---|---|---|
| 输出链路定位 | Presence 参与、Semantic/Instance 融合和多角色组合 | 角色干预有非加性，Presence 与 Instance 耦合强；不能把单角色收益相加预测整体 | 保留原生 grounding 与主要融合，anchor admission 仅作配置中的辅助 |
| 文本补充定位 | 同义/描述、统一替换、按角色残差 | 补充文本不是越多越好；职责不同，适合的补充也不同；anchor 提供稳定类别基础 | 形成 Role-Functional Text |
| 内部结构尝试 | PE 中间层、Block23 边界、逐层 clamped Replay、FCRA/类别校准 | 存在可诊断信号不等于可以纠正预测；强制拆解共享状态破坏已有耦合 | 不再调层、路由或扩大规则 |
| 视觉观察尝试 | Shared Canvas、Local/Global、固定 R0–R14 与 Joint Profile | 额外视野含信息，但统一使用方式不稳定；文本配置会改变视图的实际价值 | 形成 Joint Role–View |
| 主方法确认 | 残差/直接替换、八遥感数据集、自然图像扩展 | 残差是可靠默认；Joint 结果整体提高，但严格超加性交互不是所有数据集都有 | 数值与例外集中保留在 state §5 |
| 单图对照（2026-09-04完成） | Potsdam/Vaihingen 单图256/512视图 | 不访问相邻图像，检验图内视觉互补 | 最佳均为Global，58.59/62.33；Role保留，View无额外最优增益；[完整分析](2026-09-04_单图Role-View实验分析.md) |

失败方法按三类 limitation 归并：**不可靠自反馈、破坏共享 grounding、把相关信号当作可操作的纠错证据**。这些是测试过的实现结论，不是对所有同类方法作永久否定。具体关闭清单见 state §8；不重新设立待调参项目。

### 12.2 Interrupted-evaluation resume on 2026-08-31

- VOC20 Joint Role–View initially stopped after `200/363` distributed iterations; the subsequent resume completed the full validation set (results in §5.6).
- `tools/run_domain_extension_joint_profile_v1.sh voc20-resume` now reads the existing rank JSONL files, follows `ImageSets/Segmentation/val.txt`, runs only the remaining tail into a new shard, verifies completion, deduplicates any intentional overlap by image path, and then invokes the unchanged Joint summary.
- The same generic resume planner replaces the old iSAID-specific planner without changing the iSAID resume protocol. Baseline and model-forward behavior are unaffected.
- The VOC20 tail subsequently completed all `1,449` unique images. Final aggregation initially stopped because the summarizer incorrectly treated per-image `global_source` as dataset-constant; VOC20 legitimately mixes `full_image` and `aligned_context` according to image size. The summary contract now records their counts instead of rejecting this intended per-image variation. The tail-only `97.13` mIoU printed by MMEngine is not the full-validation method result.

### 12.3 Main-method theory/code check on 2026-09-03

- Checked active baseline, native grounding, role residual, coordinate restoration, view fusion and metric/profile-selection paths at commit `1b3b1d3`; no algorithm code changed and no new GPU inference was required.
- Eight remote reproduction CSVs report native-prompt parity and reference-identity errors both `0`; the original six-dataset final closure reproduces the selected Joint results. Historical Role-only chains differ by up to about `0.018` mIoU, so use matched references rather than claiming all earlier versions are bit-identical.
- Corrected document-only mismatches: the omitted inner Presence factor, overstated independent-role language, ambiguous per-head cross-view routing, and stale filename. Current code uses full grounding per prompt and post-P/S/I class-score View Evidence Fusion.
- `joint_role_view` is a screen: MMEngine returns official predictions while separately logged variant confusion matrices contain method results. `joint_role_view_final` returns the compiled selected method as `pred_sem_seg`.
- The frozen final registry currently covers the original six datasets. UAVid/iSAID/natural-domain results are valid extension-screen variants, but their selected profiles have not yet been added to that fixed-deployment registry. Before exporting their method qualitative masks, compile the selected extension profile rather than taking the screen's official prediction.
